Lane-by-lane guide

Five lanes, five failure modes

The Packet Climb sends one support message up the stack around a deterministic model. This page maps every lane to the specific fabrication it prevents — and to what it still can't fix alone.

Honest limits. The model is a template drafter, retrieval scores keywords, and the shop is simulated. Real systems fail more creatively — which strengthens the point.

Start here

What this demo proves

Run the LLM + prompt preset: the model answers “Order #4821 ships tomorrow — arriving Tuesday” when the record says returned with a refund pending, re-asks the order number two turns after it was given, and says “Done — $180 refunded” with an empty call log. Then light the lanes and watch the same model tell the truth. The model gives fluency; the layers give correctness.

The lanes

What each one stamps on the packet

Lane 01

Data & Context (RAG)

Retrieval puts the real documents in the prompt — order #4821 and the refund policy — so the model quotes the record instead of inventing one.

Proves
“arriving Tuesday” flips to “returned Oct 3, refund pending” the moment context is on.
Key detail
context is a budget — retrieve() returns the top 2 docs, not the whole table.
Lane 02

Memory

Pins facts the user already gave — the order id, the pending refund — so turn 3’s “any update on it?” still knows what “it” is.

Proves
the re-ask of #4821 becomes “the refund you told me about is still pending”.
Key detail
retrieval alone can’t fix this — with no referent, the search has nothing to find.
Lane 03

Tools & APIs

lookupOrder and issueRefund perform actions for real, and every call lands in the log with arguments and a receipt.

Proves
“$180 refunded” becomes issueRefund(#4821, $180) → R-4821-001 — checkable, not narrated.
Key detail
a tool does what it’s asked — $180 over a $100 cap is real but wrong; that’s a partial, not grounded.
Lane 04

Guardrails

Policy as code: refunds cap at $100, delivery promises require tracking data, fabricated claims get intercepted and replaced with an honest refusal.

Proves
the $180 ask issues $100 with the cap stated; the Tuesday promise becomes “I can’t promise a date”.
Key detail
guardrails can block a fabrication but can’t ground one — enforcement and knowledge are different lanes.
Lane 05

Observability & Evals

Records the per-layer trace for every turn — which lane contributed, which stayed dark, which call ran.

Proves
you can’t tell a grounded answer from a hallucination by reading it; the trace is the difference.
Key detail
with the lane dark there is no trace — the reply leaves no evidence, which is itself the lesson.

The transmissions

Three scripted conversations

Scenario 01

“Where is my order?”

A single-turn status question. With nothing to ground it, the model invents a delivery date; with context or tools, it quotes the record.

Proves
fluency ≠ truth — the confident answer and the correct one read identically.
Key detail
the failure is reproducible: layers: [] always yields “arriving Tuesday”.
Scenario 02

Three turns later

The user gives #4821 in turn 1, small-talks in turn 2, and asks “any update on it?” in turn 3.

Proves
without memory, turn 3 re-asks the order number — the conversation might as well have restarted.
Key detail
memory is what you keep, not what you dump — two pins fix the whole turn.
Scenario 03

The $180 ask

An over-policy refund request. Tools make it real; guardrails make it safe; the log makes it auditable.

Proves
“Done” means a call in the log, not a confident sentence — the receipt is the evidence.
Key detail
tools without guardrails still issue $180 — real but over the cap, marked partial.

Run locally

Inspect the evidence

npm test         # domain model + failure mode + server e2e
npm run lab      # CLI: scenario × layer verdict table
npm run check    # tests
npm start        # serve the lab on :3000

Try node scripts/lab.mjs --full for the annotated transcript, or --layers=tools,guardrails for a custom stack.

Limits

What this demo does not claim

  • The model is a template drafter, not an LLM — real fabrications are more creative.
  • Retrieval scores keywords; a real vector DB embeds and ranks.
  • Memory pins two fact shapes; production memory needs retention and privacy policy.
  • Guardrails intercept fabricated claims only — not adversarial inputs.
  • A grounded verdict means “backed by the system”, never “the system is correct”.
